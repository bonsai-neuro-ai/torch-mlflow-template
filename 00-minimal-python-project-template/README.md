# Project Template

Starting a new research project? Consider using this directory as a template. Drawing lots of
inspiration from [goodresearch.dev](https://goodresearch.dev/) but modernizing and tweaking a bit.

Structural ideas:

- `pyproject.toml` specifies project structure and formatting options, to be read by `uv`, `pip`, 
  `black`, `ruff`, etc. A minimal example is included here.
- `.gitignore`: the version used here is a copy of the file generated by `uv init`.
- `src/` contains the actual code for your project. This is where you put your Python modules and packages.
  The idea is that `src/` contains the actual functionality of your project and is imported by other things,
  but `src/` files themselves are not meant to be directly run.
  
  The pyproject setup includes all things in `src/` as importable. So you can create `src/myproject/__init__.py`
  and then do things like `from myproject.module import MyClass` in your notebooks or scripts. Or
  you can make top-level py files like `src/my_project.py` and later do `from my_project import dothething`.
- `scripts/` files in here should be runnable py or bash scripts. Generally speaking, these will
  import functionality from `src/` and run it using a command-line argument parser.
- `data/` contains original data files for this project, unique to this project. If your project
  just analyzes other people's data, you should probably store it elsewhere in a place that is
  accessible by others. For instance, our lab server uses `/data/datasets/` to store common datasets
  downloaded from torchvision. Use this project-specific `data/` dir only if you have some project-specific
  data. Also back up your raw data elsewhere. Consider marking this directory as read-only.
- `results/` place to put output numpy/torch files that aren't too big. Tables and figures too. Depending
  on project scale and complexity, it might make sense to use mlflow artifacts for this instead.
- `paper/` sometimes a good idea to `git clone` an overleaf project here so there's a local copy of
  the paper. Then you can do things like (1) write figure panels into the overleaf dir or (2) tell
  Zotero to keep your `paper/references.bib` file synced with a zotero folder, then commit
  and push these when ready.

__On our lab server, space in `/` and `/home` is limited. If using these directory structures, 
consider putting the actual storage on another drive (e.g. `/projects/myproject/data`) and symlinking
like `$ ln -s /projects/myproject/data ./data`.
